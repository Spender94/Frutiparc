# Les langues du parc — guide de la traduction

Frutiparc parle français et anglais. Ce guide dit comment écrire un texte
traduisible, où vivent les traductions, et ce qu'on ne traduit pas.

## Le principe : le français reste dans le code

```js
el.textContent = T('chat.rejoint', '{nom} a rejoint le salon', { nom: pseudo });
```

* Le **français** est l'argument de repli de `T()` : on le lit en ouvrant le
  fichier, les tests le vérifient, les joueurs francophones le voient. Il n'y a
  **pas** de dictionnaire français.
* L'**anglais** vit dans `public/i18n/en/<zone>.js` (`FPI18n.ajouter('en', {…})`),
  chargé seulement quand la langue est l'anglais (`FPI18n.charger([...])` dans le
  `<head>`). Une clé absente retombe sur le français : on peut traduire zone par
  zone sans rien casser.
* Un jeu a son propre dictionnaire : `public/<jeu>/lang/en.js`, chargé par
  `FPI18n.charger('/<jeu>/lang/{lang}.js')`.
* Le module est `public/js/i18n.js` (navigateur et serveur, sans étape de
  construction). Côté serveur, pas de langue courante :
  `FPI18n.traduire(langue, cle, fr, params)`, avec `langueDe(pseudo)` et
  `langueDeRequete(req)` dans `server.js` — voir « Côté serveur » plus bas.

## Écrire un texte traduisible

| Cas | Écrire | Pas |
|---|---|---|
| Texte simple | `T('club.titre', 'Le club')` | `'Le club'` |
| Avec variables | `T('k', '{nom} a gagné {n} kikooz', { nom, n })` | `nom + ' a gagné ' + n + ' kikooz'` |
| Pluriel | `T.n('k', n, { one: '{n} message', other: '{n} messages' })` | `n + ' message' + (n > 1 ? 's' : '')` |
| Grammaire qui ne tient pas dans un gabarit | une **fonction** dans le dictionnaire anglais : `'k': (p) => …` | des morceaux de phrase recollés |
| Date | `T.date(d, 'court' \| 'long' \| 'heure' \| 'jourHeure')` | un tableau de mois en français |
| Nombre | `T.nombre(n)` | `toLocaleString('fr-FR')` |
| HTML statique | `<span data-i18n="cle">Texte</span>`, `data-i18n-html`, `data-i18n-attr="title:cle;placeholder:cle"`, puis `FPI18n.appliquer(racine)` | — |

* **Une phrase = une clé.** Jamais de phrase recollée de morceaux traduits à
  part : l'ordre des mots change d'une langue à l'autre.
* **Le pluriel français** met 0 au singulier (« 0 fruit ») ; l'anglais au
  pluriel (« 0 fruits »). `T.n` le sait (Intl.PluralRules).
* **Les clés** : `zone.sujet` en camelCase français (`light.salonRejoint`,
  `forum.repondre`). Une zone par fichier de dictionnaire.
* **Les textes du serveur** (messages d'erreur, lignes système du chat,
  historiques) ne se traduisent PAS dans le client : le serveur les rend
  dans la langue de chacun (« Côté serveur », plus bas). Dans le client, on
  traduit ce que le client écrit lui-même. Quand le serveur envoie un CODE (`error: 'auth'`,
  `k="401"`), le client choisit son texte à partir du code.
* **Ce qui sert d'identifiant ne change pas** : noms de rubriques du forum,
  noms d'accessoires (« Bananocle »), identifiants de salons, de dossiers. On
  traduit l'affichage, jamais la valeur.
* **Les images qui portent du texte** : on garde l'image française ; en anglais,
  un remplaçant (texte CSS de préférence, sinon une image `-en`) :
  `.img-fr` / `.txt-en` et `html[lang="en"]`.

## Le glossaire (choix de l'admin)

On garde les mots maison : **kikooz**, **frutiz**, **bouille** (frutibouille),
**frutisign** (frutisigne), **totoche**, **FD** (le disque de partie classée).
Les noms des jeux et des personnages ne changent pas (Swapou, Frutisnake,
Kaluga, Gaspard, Gromelin, M'dam Irma…).

| Français | Anglais |
|---|---|
| salon | chat room |
| code secret | secret code |
| pseudo | username |
| parrain / filleul | referrer / referral |
| bureau Frutiz | Frutiz desktop |
| défi du jour | daily challenge |
| classement | rankings |
| Prunostics | Prunostics |
| quête(s) de Gromelin | Gromelin's quest(s) |

**Les jeux de mots** (noms de fruits de Frutisnake, niveaux de Mini-Wave,
combos de Swapou…) restent en français dans un premier temps ; ils seront
adaptés en vrais calembours anglais plus tard.

**Le ton** : le parc tutoie ses joueurs et parle avec humour ; l'anglais reste
familier et enjoué (« Want to save your scores? Sign up! »), sans traduction
mot à mot.

## Côté serveur

Ce que le SERVEUR écrit (lignes système du chat, réponses aux commandes,
émotes, PNJ ; demain historiques, notifications, courriels, catalogues) se
rend dans la langue de qui le lit. Même principe que dans le navigateur : le
français est écrit dans `server.js`, là où la phrase part ; l'anglais vit dans
un dictionnaire.

**Les dictionnaires** : `i18n-serveur/<langue>/<zone>.js`, HORS de `public/`
(le navigateur n'a pas à les télécharger). Chaque fichier exporte un objet,
chargé au démarrage (`FPI18n.ajouter('en', require(…))`) :

```js
// i18n-serveur/en/gaspard.js
module.exports = {
  'gaspard.bonjour': 'Hi {nom}!',
  'gaspard.cadeau': { one: 'Here\'s {n} kikooz for you!', other: 'Here are {n} kikooz for you!' },
  'gaspard.accord': (p) => (p.genre === 'F' ? 'She' : 'He') + ' is in',
};
```

Une zone par fichier, et chaque clé commence par le nom de sa zone
(`gaspard.js` → `gaspard.*`) : `test/chatLangues.test.js` le vérifie. Zones
existantes : `chat` (lignes système, commandes, émotes, page des logs),
`irma`, `frutisigne` (les dix noms : `nomDeFrutisigne(i)`, et le mot du jour
de frutisignes.js), les PNJ — `gaspard`, `gromelin` (le chat, et ses répliques
de la fenêtre des quêtes), `kiloute` (MikeHorny), `loupgarou` (voir « Les PNJ »,
plus bas) —, et celles de l'API et des catalogues :

| Zone | Ce qu'elle traduit |
|---|---|
| `api` | les messages des routes de joueurs : inscription, connexion, code secret oublié, forum, courrier, compte |
| `pictos` | les noms des pictos par identifiant (`pictos.$butterfly0`) et les gabarits des familles (« Monstre {n} ») ; l'album de JamaJama |
| `boutique` | les refus, les rayons, la fiche commune, les articles livrés avec le code (`boutique.<id>.nom`, `.description`, `.commentaire`) |
| `classements` | les noms des classements, les onglets du tableau des scores, les étiquettes de score, les médailles |
| `prefs` | les préférences du light (libellés, descriptions, choix, catégories, feutres) |
| `profil` | les pays de la fiche et du profil |
| `rubriques` | les noms à afficher des rubriques du forum, et leurs descriptions d'origine |
| `quetes` | les quêtes de Gromelin : titres, lignes, unités, niveaux, paliers, refus |
| `paris` | les Prunostics : refus, ce que dit chaque pari, l'affiche d'un match |
| `tournois` | le nom des tours (tournoiDuel.js, tournoiCoupe.js) |

**Les fonctions** (`server.js`) :

| Fonction | Rôle |
|---|---|
| `t(lang, cle, fr, params)` | `FPI18n.traduire` |
| `tn(lang, cle, n, formes, params)` | `FPI18n.pluriel` |
| `texteDe(lang, texte)` | rend un **texte traduisible** (ci-dessous) |
| `langueClient(client)` | la langue d'une socket du chat (`'fr'` par défaut) |
| `langueDe(pseudo)`, `langueDeRequete(req)` | celle d'un compte, d'une requête HTTP |
| `tReq(req, cle, fr, params)` | un texte dans la langue de la requête (les `message` des routes) |
| `nomDePicto(id)`, `nomDeMedaille(m)` | un picto, une médaille, en texte traduisible (à passer en paramètre) |
| `getGameItemDisplayName(id, lang)`, `nomDeClassement(id, lang)` | le nom d'un picto, d'un classement |
| `texteArticle(article, champ, lang)`, `nomPossede(objet, lang)` | un article de la boutique, un objet possédé |

**L'API.** Une route de joueur écrit son `message` (ou son `error` en toutes
lettres) avec `tReq(req, 'api.…', 'le français')`. La langue de la requête :
le compte si elle porte un sid, sinon le `lang` de la page (l'accueil
l'envoie à l'inscription, à la connexion et au code oublié), sinon
`Accept-Language`. Les CODES d'erreur ne se traduisent jamais. L'admin reste
en français.

**Les catalogues** se rendent à la lecture : le nom français reste
l'identifiant (un accessoire, une rubrique du forum, un rayon), on traduit ce
qu'on affiche — au besoin dans un champ à part (`libelle` d'une rubrique,
`cle` d'un rayon de la boutique). Un article de la boutique saisi dans
l'admin porte son anglais en base (`name_en`, `description_en`,
`comment_en`) ; un article livré avec le code, dans le dictionnaire, tant que
la base garde le français du code. Les jeux de mots (les fruits de
Frutisnake) restent en français.

**Les quêtes** ne rangent plus leurs textes : une définition porte ses
paramètres (et `rendu` pour sa ligne de détail), quetes.js refait titre et
ligne à chaque lecture (`Quetes.titre(def, lang)`, `Quetes.detail(def, lang)`,
`Quetes.avancement(def, etat, lang, periode)`). Une semaine rangée avant se
relit encore : un texte que le code aurait écrit à l'identique se refait.

**Un texte traduisible** — ce qu'on passe au lieu d'une chaîne française
quand la phrase part vers des lecteurs de langues différentes :

```js
'texte'                                   // le même pour tous (un pseudo, ce qu'un humain a tapé)
{ k: 'irma.bonjour', fr: "B'nj'ur !", p: { nom } }          // une clé
{ k: 'chat.quiz.points', n, formes: { one, other }, p }      // un pluriel
(lang) => '…'                             // tout le reste (ne se refait pas au rejeu)
```

Un paramètre peut être lui-même un texte à clé :
`p: { signe: nomDeFrutisigne(3) }` dit « fraise » ou « strawberry ». On n'y
met que des valeurs (chaînes, nombres, textes à clé), jamais de fonction :
les paramètres sont rangés avec la ligne.

**Le chat : une trame par langue.** Les salons sont partagés.
`broadcastToChannel(salon, trame)` (et `annonceModeration`, `chuchoter`,
`lgPublic`/`lgInfo`/`lgSecret`, `envoyerTrame(sock, trame)`) acceptent :

* une chaîne — la même pour tous, comme avant ;
* `(lang) => xml` — une trame par langue ;
* `{ build: (lang) => xml, k, kp }` — la même, qui sait se refaire au rejeu.

Chaque langue n'est rendue qu'une fois par envoi, toutes sous le même `mi`, et
le français sort octet pour octet comme avant. On n'écrit presque jamais le
troisième cas à la main :

```js
// Une phrase dans son habit (le cas courant) : `html` est la phrase rendue
// et échappée ; tout ce qui l'entoure est l'habit.
broadcastToChannel(g, ligneTraduite(
  { k: 'chat.modo.appel', fr: '{nom} indique qu\'il y a des problèmes sur ce salon !', p: { nom } },
  (html) => `<t u="admin" … st="r"><![CDATA[<font color="#C10000"><b>${html}</b></font>]]></t>`));

// Une réplique de PNJ : npcSay / npcSaySequence prennent des textes traduisibles.
npcSay('gaspard', g, { k: 'gaspard.bonjour', fr: 'Salut {nom} !', p: { nom } });
```

Une ligne qui ne tient pas dans ce moule (plusieurs phrases, du HTML DANS la
phrase, un attribut à traduire) déclare son rendu, qui sert au direct comme
au rejeu — voir le classement (`chat.quiz.classement`), le dé (`chat.de`) et
les émotes (la famille `chat.emote.`, dont le rendu refait aussi `el`) :

```js
rendreLigne('chat.de', (lang, p) => ({ corps: `<![CDATA[${t(lang, 'chat.de', '{qui} lance un dé…', …)}]]>` }));
broadcastToChannel(g, ligneRendue('chat.de', { nom, faces, tire }, (r) => `<t …>${r.corps}</t>`));
```

Une réponse qui ne va qu'à celui qui tape : `t(langueClient(client), …)`, sans
plus (dans `case 'send'`, la langue de l'auteur est déjà dans `L`).

**L'historique** (rejeu du light, page des logs, table `chat_history`) range
la version FRANÇAISE, augmentée de ` k="clé" kp="{json}"` quand la ligne a une
clé. `retraduireTrame(xml, langue)` ôte ces attributs et refait la ligne dans
la langue du lecteur — y compris après un redémarrage. Garde-fou : une ligne à
clé que le rejeu ne referait pas exactement comme le direct est rangée sans
clé (elle se relira en français), et le journal dit
`[i18n] ligne non rejouable dans le moule : <clé>` — signe qu'il lui faut un
`rendreLigne`.

**Ce qui est rangé ou poussé** (étape 3b, `test/historiqueLangues.test.js`) —
zones `historique` (l'historique, les évènements que le site écrit seul,
l'Historique Kikooz, les titres en code du frutijob), `notif` (les
notifications poussées), `mail` (les courriels) et `forumbots` (Natacha,
Dimitri, VieuxPruneau). La grammaire anglaise que leurs entrées-fonctions
partagent (ordinaux, listes, nombres, dates) est dans
`i18n-serveur/outils-en.js`, hors de `en/` :

* **L'historique** (`addAndNotifyUserLog`, `addUserHistoryEntry`,
  `addSiteHistoryEntry`) prend un texte traduisible. L'entrée garde son
  FRANÇAIS dans `content` (le bureau Flash le lit tel quel, et le code qui
  cherche une entrée par son contenu — la suppression d'une annonce, la
  marque 🎂 de l'anniversaire — continue de marcher) ; un gabarit range en
  plus sa clé et ses paramètres (`user_logs.msg_key`, `msg_params`, et `k` /
  `kp` en mémoire). `texteEntree(langue, entrée)` la refait à la lecture : le
  light (`/api/light/history`, `/api/light/events`), la trame `<aw>` en
  direct et au rejeu de l'ident. Une vieille ligne, ou une annonce tapée par
  l'équipe, se lit telle quelle.
* **L'Historique Kikooz** : le motif d'un « obtenus par » est un code
  (`kikooz_log.label_key`, `label_params`) ; les anciens libellés français,
  en nombre fini, retrouvent le leur à la lecture (`MOTIFS_KIKOOZ_ANCIENS`).
* **Les notifications poussées** : `t` et `c` sont des textes traduisibles,
  rendus appareil par appareil (`chargeDansSaLangue`) dans la langue du
  compte — rangée avec l'abonnement (`push_subscriptions.lang`) pour un
  absent dont le compte n'est pas chargé.
* **Les courriels** partent dans la langue du compte.
* **Les personnages du forum** : Natacha écrit au nouveau dans SA langue ;
  Dimitri et VieuxPruneau, qui parlent à tout le monde, ajoutent sous le
  français une version anglaise, en italique sous un trait, dans le MÊME
  message (`forumBilingue.js`) — la marque de la graine, le message du jour
  que Dimitri complète en le modifiant, et les sujets retrouvés par leur
  titre français restent ce qu'ils étaient.

**Qui lit quoi.** La langue d'une socket est le `la` que la page annonce à
l'ident (le light). Le bureau Flash d'époque n'annonce ni `la` ni `lc` : il
reste en FRANÇAIS, quelle que soit la langue du compte (c'est un SWF compilé).
La page des logs (`/api/chat/histo`) suit `?lang=`, sinon la langue du compte.

**On ne traduit pas** : les messages des joueurs, le cri rouge d'un modérateur,
les annonces de l'équipe, les questions des quiz et sondages d'un animateur
(`/initpoint`, `/poll`), les sujets de salon — ce sont des textes d'humains.
(Ce que l'admin écrit pour un PNJ — rubrique d'aide, question de MikeHorny —
a, lui, sa version anglaise facultative : voir « Les PNJ ».) Les mots d'émote anglais (`haha`, `cry`,
`wink`, `gross`…) déclenchent les mêmes animations que les français, tapés
seuls ; ils sont dans les deux tables (`CHAT_EMOTES`, `EMOTE_MAP` du light).

**Essayer** : deux onglets du light, l'un en `?lang=fr`, l'autre en
`?lang=en`, dans le même salon ; `POST /api/admin/visiteurs/irma`
(`{ salon, pas }`, clé d'admin) fait passer M'dam Irma tout de suite, `pas`
en millisecondes entre deux répliques. `test/chatLangues.test.js` fait le
tour de tout cela, rejeu et redémarrage compris.

### Les PNJ

Chaque réplique de PNJ est un texte à clé ; le français reste à l'endroit où
elle part, l'anglais adapte la voix du personnage (pas de mot à mot) :
Gaspard l'hôte serviable, Gromelin le bougon (« Grumpf »), MikeHorny
l'animateur de jeu télé, le meneur du loup-garou. `test/pnjLangues.test.js`
les fait parler devant un francophone et un anglophone du même salon.

* **Une banque de phrases** (MikeHorny, les nuits du loup-garou) : chaque
  phrase a la clé de son rang — `kiloute.bravo.3`, `loupgarou.nuits.2`. Le
  tirage est le même pour tous ; chacun lit la phrase tirée dans sa langue.
  Une banque à trous est une liste de fonctions qui rendent le texte à clé.
* **Ce que l'admin écrit dans les deux langues** (une rubrique d'aide, une
  question de quiz, le nom d'un quiz) : les deux versions sont des
  PARAMÈTRES d'une clé dont l'anglais choisit (`kiloute.libre` :
  `(p) => p.en || p.fr` ; `gaspard.rubrique`). La ligne se refait donc au
  rejeu, et sans anglais tout le monde lit le français. En base : les
  colonnes `*_en` (`gaspard_help_topics.title_en/body_en/keywords_en`,
  `kiloute_questions.question_en/answers_en/reveal_en`, `quizzes.name_en`) et
  `qEn/aEn/rEn` dans le JSON des questions d'un quiz ; dans l'admin, les
  champs « EN ». Pour un quiz, les réponses anglaises S'AJOUTENT aux
  françaises (`kilouteReponses`) : un salon mêlé répond dans les deux.
* **Gaspard comprend les deux langues.** `gaspard.js` lit chaque question
  deux fois : en français (ses mots vides, `racine`, les `mots` de BASE) et
  en anglais (`MOTS_VIDES_EN`, `racineEn`, `MOTS_EN`, pesés : `werewolf:2`).
  La langue de la question (`langueDeQuestion`, ses mots vides) dit quel
  lecteur écouter d'abord ; une question française reçoit la réponse
  d'avant. Ce qu'il choisit est une CLÉ de réponse (`gaspard.reponse.<clé>`),
  dite ensuite dans la langue de chaque lecteur.
* **Le loup-garou** (`loupgarou.js`) : chaque événement garde son français
  dans `t` et porte sa forme traduisible dans `tr`. Les noms des rôles,
  « A (n°1) », la composition du village, les listes (`liste`) et les lignes
  (`lignes`) sont des paramètres à clé. Ses lignes ont du gras et des
  retours à la ligne : la famille `loupgarou.` déclare son `rendreLigne`.
  La vue JSON du mobile (`vue(…, lang)`) suit la langue de la socket ; `/lg`
  comprend aussi les verbes anglais (`join`, `vote`, `devour`, `see`…).
* **La fenêtre des quêtes** (HTTP) : `Quetes.parole(clé, vars, alea, lang)`,
  dans la langue du compte (`gromelin.parole.<clé>.<rang>`).

Les titres et détails des quêtes, et les messages que les PNJ postent au
forum ou dans l'historique, sont traduits à part (catalogues, historiques).

## Hors champ

* Le bureau Flash d'époque (`/legacy`) reste en français (SWF compilé).
* La page d'administration reste en français.
* Les messages des joueurs, du forum et des mails ne sont jamais traduits.

## Les jeux

* Chaque page de jeu charge `/js/i18n.js` tout en haut de son `<head>` (juste
  après `/js/sid-discret.js` et avant `/js/invite.js`), puis
  `FPI18n.charger(['commun', 'widgets', '/<jeu>/lang/{lang}.js'])`.
* Le dictionnaire d'un jeu : `public/<jeu>/lang/en.js`, clés `<jeu>.*`.
* Les grands tableaux (répliques, listes de mots, noms d'ennemis) :
  `T.table('<jeu>.repliques', REPLIQUES_FR)` — la traduction est un tableau de
  même forme ; un élément manquant retombe sur le français.
* Le panneau du mode invité (`FPInvite.finDePartie`) prend `libelleEn` /
  `titreEn` à côté de `libelle` / `titre`.
* Les polices réduites (sous-ensembles extraits des SWF) n'ont souvent que les
  glyphes de 2004 : vérifier que le texte anglais s'y écrit, sinon passer à la
  version complète de la même police ou à une police système proche.
* Les textes gravés dans les images (logos, boutons dessinés) : on garde
  l'image française ; l'anglais vient d'un texte posé à l'exécution ou d'une
  image `-en`. Les noms de jeux ne changent pas. Exemple : Swapou réécrit
  « victory! », « you lose! » et le sous-titre de son logo dans la fonte
  embarquée et l'habit des images (`SwapouUI.lettrage`), sur un logo dont le
  sous-titre a été ôté (`scripts/swapou-logo-sans-sous-titre.js`).
* Un jeu dont le code tourne aussi SANS i18n.js (Swapou : le rejeu des
  parties sur le serveur, les tests en bac à sable) passe par un relais qui
  rend le français tel quel quand `T` manque (`SwapouUI.tr`).
  D'autres façons, selon le jeu :
  * **JamaJama** redessine ses textes figés avec les contours des fontes du
    SWF (`scripts/build-jamajama-anglais.js` → `sprites/paquet-en.json`,
    chargé en anglais seulement) ; SkaterDudes, la fonte du menu, est
    complétée par les glyphes de l'intro du jeu, et les mots anglais sont
    choisis pour s'écrire avec ;
  * **Frutisnake** tire de ses dessins une version NUE
    (`scripts/build-snake3-anglais.js` → `sprites/en/`), que la table
    `snake3.dessins` du dictionnaire substitue, et écrit l'anglais par-dessus
    dans le style de l'original.
* L'aide de JamaJama : `Games/poulpi/help-en.xml`, que `/api/jamajama/aide`
  sert quand la requête est en anglais (le jeu envoie `?lang=`).
* Les JEUX DE MOTS (noms de fruits, de niveaux, de combos) restent en français
  pour l'instant.
* Un module qui sert aussi sous Node (les tests chargent menu.js, client.js…)
  ne suppose pas FPI18n : un petit `tr(cle, fr, p)` retombe sur le français,
  gabarit rempli. Les tableaux que le serveur ou les tests relisent (noms
  d'épreuves, de paliers, de grades) gardent leur français ; on traduit à
  l'affichage, par l'identifiant.
* Les tests Playwright : le Chromium de Playwright dit `en-US`, donc une page
  traduite s'y ouvre en ANGLAIS. Un test qui lit ou clique du français pose
  `locale: 'fr-FR'` (ou `fp_lang`). `test/i18nJeuxA.test.js` montre comment
  relever les textes d'une toile (un espion sur `fillText`) et vérifier qu'ils
  tiennent et s'écrivent dans leur police.
* Déjà traduits : Grapiz, Frutibandas (noms des cartes : ceux des bannières
  anglaises d'origine, `assets/advertiser/`), Mini-Fever, Miniwave 2.
* **Les phrases tirées au sort** (MiniPixiz : missions de Gromelin, répliques
  de la fée, nuits) : le hasard tire un RANG dans la table française — sa
  longueur, ses trous (une case nulle est un silence) —, puis on lit la case
  de même rang dans la table traduite (`MinipixizLangue.dansLaLangue`). Le
  hasard consommé ne dépend donc jamais de la langue ; la table anglaise a la
  même forme, cases nulles comprises.
* **Les phrases assemblées** ne recollent pas de morceaux traduits : chaque
  langue a ses propres CANEVAS (articles, prépositions, ordre des mots) et ses
  listes de mots n'en portent que ce qui leur revient (« the mill » là où le
  français range « du moulin »). Un jeton à majuscule (`$Kingdom`) donne le mot
  avec sa capitale en tête de phrase. Ce qui est RANGÉ dans une sauvegarde
  reste en français (le format du SWF) et se refait à la lecture
  (`phraseDeFinDansLaLangue`). `test/minipixizLangues.test.js` épingle le
  français d'avant (une empreinte SHA-256) et vérifie que l'anglais ne change
  ni la fiche ni le hasard.
